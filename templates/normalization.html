Normalization: 1NF to 3NF

Example: a library records which member borrows which book. The initial design repeats member and book details for every loan.

Unnormalized form (UNF)

LoanRecord(member_id, member_name, member_email,
            {book_id, title, author_name, loan_date, due_date})

Problem: a member can have multiple books in one repeating group; values are not atomic.

First Normal Form (1NF)

LoanLine(loan_id, member_id, member_name, member_email,
         book_id, title, author_name, loan_date, due_date)

Each row represents one book loan and every cell contains one value. A possible key is (loan_id, book_id).

Second Normal Form (2NF)

With the composite key, member details depend only on loan_id, while book details depend only on book_id. Move them to separate relations to remove partial dependencies.

Members(member_id PK, member_name, member_email)
Books(book_id PK, title, author_id FK)
Loans(loan_id PK, member_id FK, loan_date)
LoanItems(loan_id PK/FK, book_id PK/FK, due_date)

Third Normal Form (3NF)

Author name depends on author_id, not directly on book_id. Store author details separately, removing the transitive dependency.

Authors(author_id PK, author_name)
Books(book_id PK, title, author_id FK, price)

Result: member, author and book facts are stored once; foreign keys connect the relations. The final schema is in sql/schema.sql.
